# ToolShift 实验协议

版本：1.0；日期：2026-10-20。本协议定义测量方法与拒绝错误结论的条件。结果以实际运行产物为准；本文件中的阈值和规模是计划，不是实验成绩。

## 1. 问题与研究假设

工具升级后，接口形式可能不变，但数值单位、集合更新和默认作用范围发生变化。Agent 在旧文档下完成一个至少包含两个必要写步骤的任务，可付费读取少量新证据。目标是完成任务并保留所有受保护状态，同时减少不必要查询。

- **H1，动作充分性：** 对完成任务而言，明确一个共同正确动作可能早于识别唯一工具版本；动作充分性监督应减少无用查询，尤其在不同版本行为等价或可显式指定 scope 时。
- **H2，后续可完成性：** 只检查当前动作不触发不变量不足以判安全；监督须考虑不可回退写入是否使后续目标失去可达性。
- **H3，学习的必要性：** 在家族、模板或变更组合留出后，学习策略仍须对强静态规则和同预算普通监督产生价值。若静态规则已达到上界，结果应报告为可控环境被规则解决，不能包装成学习突破。

## 2. 有限世界与可见信息

首版初始业务状态公开，时间冻结，无并发外部修改；隐藏变量仅在有限 WorldSpec 中，包含单位、更新模式、默认范围及查询可观测性。未来若加入隐藏业务状态，可能世界必须扩充为 `(版本, 隐藏状态)`，不能继续仅以版本索引推理。

策略可见：用户目标、旧契约、初始状态、公开工具/查询/候选描述、预算、实际获得的查询与动作结果，以及主实验显式提供的 `uncertainty_contract`。该契约描述各维度允许值及是否构成笛卡尔积，必要时使用去掉世界 ID 的完整候选语义列表；它由完整可能支持集生成，与被选中的真实世界无关。策略不可见：真实 WorldSpec、world ID、真实模式、oracle 的后验集合/最优值/允许动作集合、未查询的返回值、数据库对象。

**已知候选变化范围是额外部署假设。** 所有静态方法、学习方法和 oracle 都获得相同公开范围。不能把 teacher 按私有 suite 缩小的可能世界集藏起来，否则相同公开观测可能被标成一会直接写、一会必须查询，形成不可实现监督。本项目不是未知世界发现；若真实版本超出支持集，只能报告模型失配与暂停/失败，不能沿用有限模型保证。

同任务、同公开候选支持集的不同真实世界必须序列化出完全相同的初始公开输入。同公开支持集、历史和预算必须得到相同的 acceptable set。候选动作可以由公开任务生成，但不能按真实隐藏世界筛选。固定候选空间是首版限制，应与自由生成工具参数的 LLM agent 区分。

## 3. Oracle 定义与计算边界

设公开历史为 \(h_t\)，与之相容的有限世界集合为 \(B_t\)。每个世界同时包含其执行到当前历史后的状态。只读查询 \(q\) 的确定返回将 \(B_t\) 划分为 \(B_{t,q,o}\)。查询成本严格为正；不产生新信息的重复查询不能降低最优值。

“当前安全”与“可稳健完成”分开定义：

- 当前安全：执行动作后，所有剩余世界中的过程不变量仍成立。
- 可稳健完成：存在同一条依据未来公开观测决策的后续策略，在所有剩余世界中均于剩余步数/预算内完成目标并保持不变量。

仅仅每个世界各自存在一条成功计划，不足以证明存在共同的可执行策略。Oracle 必须按同一公开历史绑定决策，不能在模拟时偷偷为不同世界选择不同动作。

有限步数的动态规划在允许的剩余写次数、查询预算和 belief state 上枚举。完成态值为 0；无可行稳健完成策略值为无穷。查询分支的代价为当前成本加各返回分支最坏的后续成本；无额外副作用且具有统一可完成后继的动作分支继续递归。底层保留达到最优值的动作和查询。默认监督使用**相同最坏总查询成本时 act 优先**的显式次级规则：若存在并列最优动作，返回这组动作；否则返回并列最优查询。它是带 tie-break 的集合，不应称全体最优决策；完整最优集合应单独导出供消融。

暂停不能作为成本为 0 的“成功终点”，否则恒暂停是平凡最优。预算内无稳健完成策略时可以暂停；它属于安全未完成，不能记为任务成功。`max_actions` 使搜索有界；达到该界仍未完成是失败。

ExactOracle 是**给定有限世界模型、要求对整个支持集稳健完成的策略类内的性能上界和查询成本下界**，不是现实 API 的最优性证明，也不是允许猜测时逐真实世界成功率的上界。不可辨识任务中，一次盲猜可能碰巧完成真实世界，而稳健 oracle 正确暂停；不能据此认为 oracle 算错或盲猜策略更安全。它具有完整有限转移模型这一结构知识；只能用作监督、限定范围的上界和验证器，不混入可部署方法排行榜。报告搜索世界数、状态数、耗时及上界，防止“exact”掩盖有限范围。

## 4. 数据及切分

所有数据为项目自产的合成任务，不含真实账户、商家或日程。数值、对象名和语句变体由固定 seed 生成；公开目标与私有真值分别保存。一次样本组包含同一公开任务的全部版本分支与派生轨迹。

切分在生成轨迹之前确定，以下结果分别报告：

| 切分 | 真正留出的内容 | 不允许的替代 |
|---|---|---|
| 实例留出 | 独立 seed、对象与数值 | 不能称跨工具家族 |
| 域留出 | 当前 calendar 全部留出；将来可轮换三折 | 三域共用数值赋值/集合更新两种算子，只能称域与字段映射迁移，不能称未见算子家族 |
| 强模板留出（后续协议） | 指令结构及其同义改写族整体留出 | 当前只改指令前缀，不满足强模板留出 |
| 组合留出 | 训练单因素或部分组合，测试未见单位×更新×范围组合 | 测试组合的同源版本出现在训练中 |

所有同源公开任务的世界、前缀、查询分支和教师轨迹共享 split。split manifest 记录来源组、域、模板标签、变更组合、生成器版本与 seed。当前生成器使用局部 `random.Random(f"{domain}:{seed}")`，数值系数在 2–300 间，新增集合项从 1,000 个编号中选 2–3 个；域名进入随机流，避免相同 seed 跨域复用相同潜在数值和集合编号。仍必须按内容哈希归组/去重，不能仅凭 seed 不同认定独立。

当前 `generate_episodes` 的实际规则：`semantic_group` 去掉 task_id、seed、instruction 前缀和 query_budget 后按内容哈希归组；travel/catalog 按组哈希约 60%/20%/20% 分 train/dev/test；calendar 全部进入 test。`mixed` 只为原本属于 test 的来源组生成，绝不把 train 来源组的组合变体挪到 test。test 使用第三种文字前缀，manifest 明确称 `instance_and_prefix`，只是弱文字扰动。来源组不随查询预算变化，多预算曲线保留同任务配对。

训练集、开发集和盲测集不共享来源组。模型/规则选择仅用开发集；看过盲测失败再修改方法的运行必须升级实验版本并换新的最终留出族。

首版的三个域不构成大型统计总体。`domain` 分类含 calendar 的单因素与 mixed 任务，域变化和组合变化可能混杂；评估已提供 `by_domain_and_suite`，应据此分别展示 calendar 单因素与 mixed，不能把总体差异都归因于域外推。

## 5. 必须实现的对照

| 方法 | 可见信息与策略 | 用途 |
|---|---|---|
| `no_refresh` | 始终使用旧契约 | 测量升级伤害，不作为主要强基线 |
| `full_refresh` | 付费读取完整新契约，再执行任务 | 高信息成本基线；刷新返回不可得时如实失败/暂停 |
| `static_schema` | 根据可获得的前后 schema 做差分 | 揭示纯语义变更保持 JSON 合法的边界；新契约不能免费给它 |
| `static_semantic` | 手写任务相关依赖规则；必要时查单位/更新模式，显式限定 scope | 主要强静态基线；不能只用弱 schema 对照证明学习有效 |
| `greedy_query` | 按每单位成本降低最坏剩余歧义的贪心规则 | 与多步规划比较；使用的可能世界知识必须标明 |
| `version_identification` | 继续查询直到单一版本或预算耗尽 | 检验“识别版本”是否比“充分支持动作”多付成本 |
| `oracle` | ExactOracle，完整有限可能世界模型 | 监督与上界，独立列，不视为真实部署策略 |
| candidate scorer | 公开上下文/历史与候选文本的可训练评分器 | CPU 可运行的学习与数据通路验证；不是 LLM 微调 |
| QLoRA policy | 同公开输入，模型自己的 tokenizer 模板，assistant 目标训练 | 单卡 24GB 的大模型后训练路线，须真实训练后才报告 |

纯贪心 oracle 知识版本与纯公开规则版本应分开，不能把不同信息条件的差距归因给算法。静态语义策略若已达到 ExactOracle，须明确说明当前任务不需要学习；跨域测试和增加真实未见语义才可能提供进一步证据。

## 6. 消融与训练公平性

至少比较动作充分性集合监督、完整版本识别监督、纯贪心下一查询监督、只学成功写动作、仅单一确定教师轨迹。另做去除无漂移对照、去除查询成本、去除未来可完成性检查的机制消融。

同一模型、训练 token 或训练计算预算、来源组、seed、候选空间和推理预算保持一致。多个同样优的标签可以用集合损失或预先声明的均匀采样；单一目标采样仅是实现近似，不能称已实现严格集合目标。训练特征不能使用 belief 大小、oracle 最优成本或正确动作数，除非作为明确的特权消融，且不得列入主结果。

candidate scorer 的权重、特征词表/哈希、训练配置和 seed 要存档。QLoRA 从同一模型 revision 开始，记录底模与 tokenizer 哈希、量化方式、LoRA 配置、目标模块、最大长度、batch、累积、学习率、scheduler、精度及 checkpoint。权重许可在下载前登记。

本机是 Apple M4 Pro、24GB 统一内存；CPU 通路可验证数据、候选评分器及评估器，具备依赖后可另测 MPS 普通 LoRA。它不等价于 NVIDIA 24GB 显存，也不能由此推断 CUDA/NF4 QLoRA 可运行。CUDA 24GB 路线从 1.5B–3B、小 batch、短上下文开始，先测峰值显存和有效训练 token；本机 MPS 从实际可装载的更小模型起步并独立报告。没有实际硬件/权重/依赖时状态写“未运行”，不生成虚构损失曲线或 LLM 分数。量化与模板实现依据 [PEFT 官方文档](https://huggingface.co/docs/peft/developer_guides/quantization) 和 [Transformers 模板文档](https://huggingface.co/docs/transformers/chat_templating)，具体依赖版本由执行环境锁定。

## 7. 指标与统计

首先区分两种成功：**实际结果成功**指真实世界最终目标满足、过程保护状态未破坏，并在预算/步数内完成；**稳健策略成功**还要求每次动作在当时公开信息对应的整个支持集上保持统一可完成性。当前评估分别记录 `success` 与 `robust_success`，并由私有评估器检查动作是否属于当时 oracle 的 safe_actions；`uncertified_actions` 记录未通过该检查的动作数。检查结果不能返回策略，也不能在执行前替策略修正动作。

该审计覆盖当前实际执行路径上的写动作，保证仅相对于声明的有限支持集和剩余动作界；它没有运行策略在所有未执行查询分支上的决策，不能当成策略整体或现实环境的无条件保证。

不可辨识组上“猜中”的实际成功单列，不能与 oracle 安全暂停混成普通成功率竞争。主要机制结论应在同稳健安全约束或可解任务集内比较，同时保留全部任务结果，避免通过删除困难任务夸大性能。

同时报告：

- 所有 episode 的平均查询次数、查询成本、动作数；成功条件下的查询成本另列，避免只保留容易成功样本。
- 安全未完成/暂停率；不可辨识任务上的错误执行率；可解任务上的不必要暂停率。
- 不可辨识任务上碰巧完成真实世界的比例；若实现了稳健动作审计，另报支持集上的不安全行动率。
- 无漂移或行为等价任务的误修复率与多余查询率。
- 过程不变量破坏、目标失败、格式错误、超预算、执行器异常分别计数。
- 成对基线成本差和成功差、预算—成功曲线、每域/每变更类型分解。
- 实测 wall time、CPU/GPU 资源与训练成本。若 `wall_seconds` 包含私有 oracle 证书审计，应标为端到端评估耗时，不能当成部署推理延时；需要比较推理效率时另计策略、环境和审计时间。无真实 tokenizer 时字符长度不能冒充 token 数。

各方法跑相同实例、真实世界和随机种子；至少三组训练 seed。置信区间按来源组聚类 bootstrap，保留组内全部版本和分支；不能把高度相关的版本实例当独立样本获得虚假的窄区间。家族仅有三类时另报告逐域值，不以三簇 bootstrap 做强泛化推断。异常不静默剔除；同时报告任务失败率和系统错误率。

预设继续门槛是：相对最强同信息、可部署基线，留出安全成功率非劣于 2 个百分点，同时查询成本至少下降 20%。非劣性判断须用配对差的置信区间，不能仅凭点估计。该门槛不是论文标准，未过门槛应报告负结果并保留工程产物。

## 8. 执行顺序与结论资格

1. CPU 真值测试：SQL 实际更新、写锁、查询只读、跨世界公开输入一致、未来可完成性反例、oracle 与穷举小例一致。
2. 数据审计：来源族切分、候选不泄漏、监督标签可复算、所有不可辨识类正确标记。
3. 所有非学习强基线；若静态已经占优，先记录结论再决定学习用途。
4. CPU candidate scorer 与监督消融；报告为有限候选策略实验。
5. CUDA/模型依赖检查、10–30 步 QLoRA smoke run、显存检查；通过后才做正式多 seed 训练与留出评估。
6. 封存配置、逐 episode 轨迹、结果和失败样例；总结实际成立的结论，不把完成测试等同于模型改进。

## 9. 当前实现覆盖与研究结论

已经落地的 v1 生成/评估实现提供显式公开支持集、真实 SQLite 两步写入、有限 oracle、static/refresh/identify/legacy/schema 控制与 CPU 学习接口。`schema` 当前实现仅按旧单位/更新语义并显式限定 scope 行动，没有运行第三方 schema-diff 引擎；它是 schema 不变条件下的旧语义控制，不能称集成 AgentCompat。v1 的纯贪心教师监督、版本识别教师监督和强模板外推仍是待执行协议项；独立诊断扩展的贪心查询对照另行报告。

H1 首先由 oracle 与手写 static 对照检验“行动所需信息少于完整版本识别”，这是任务结构的机制结果。只有训练策略在匹配条件下超过强 static，才有 H3 的学习增量证据。若 static 达到 oracle，记录这一负结果；即使训练 loss 下降、演示成功，也不能宣称学得策略更好。

首版复杂度审查与下一版的可证伪门槛另见 [scope_and_next_gate.md](scope_and_next_gate.md)。耦合诊断 CPU 扩展现已按独立 [diagnostic_graph.md](diagnostic_graph.md) 协议实现：67 个配置、374 个世界、1,870 次真实 SQLite 执行，比较精确行动充分性树、精确版本树、两种贪心与完整刷新。它未修改 v1 数据，没有训练模型，也没有完成按查询结构族留出的学习评估；其规划收益不能混入 LoRA 成绩。

SmolLM2-135M 在本机 MPS 上的 200 步 LoRA 正式训练已完成，见 [training_summary.json](../experiments/lora_main/training_summary.json)。
51-episode 独立评估也已完成：底模全部暂停，LoRA 实际成功 23 个、稳健成功 8 个、
保护约束违例 15 个，未发起查询。该结果不支持学会证据获取或超越强规则；
见 [结果与未执行项清单](results.md)。
