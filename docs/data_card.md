# ToolShift 数据卡

版本：1.0；生成机制：项目自行编写的有限工具世界；来源：独立合成 SQLite fixtures。无真实用户、账户、商品、地点或日程记录。当前数据用于研究工具语义变化后的证据查询与局部行动，不能代表真实互联网分布。

## 1. 数据单元

数据包含四个层次，数量不得混用：

1. **公开任务组**：用户目标、公开初态、工具候选和旧契约相同的一组任务。
2. **世界实例**：同一公开任务在一个隐藏 WorldSpec 下执行。
3. **episode**：某个策略、seed、预算在世界实例上的完整执行。
4. **决策记录**：episode 某个公开前缀及其集合监督；多个记录可能高度相关。

“1,000 条训练记录”不等于“1,000 个独立任务”。所有规模以实际 manifest 中的 group、world、episode 和 row 计数为准。本数据卡不预填尚未生成的规模或训练成绩。

## 2. 域与变更机制

| 域 | SQLite 表 | 两项必要写入 | 保护对象 |
|---|---|---|---|
| 出行 | `travel_records` | 设置目标时长、更新途经集合 | 非目标记录、需保留的已有集合项 |
| 商品 | `catalog_records` | 设置目标价格、更新标签 | 非目标记录、需保留的已有标签 |
| 日程 | `calendar_records` | 设置目标时长、更新参与者集合 | 非目标记录、需保留的已有参与者 |

`effect_log` 保留执行审计。所有更新都是真实 SQL 状态变更；第一次提交锁定对应字段。错误写入即使未立刻破坏保护对象，也可能让目标不再可达。

核心世界生成器的设计分组如下；它们是变更条件，不是独立业务家族：

| 分组 | 每个公开任务的世界数 | 区别 |
|---|---:|---|
| `units` | 2 | 数值单位因子不同 |
| `append_replace` | 2 | 集合更新语义不同 |
| `default_scope` | 2 | 未显式指定时的作用范围不同 |
| `unidentifiable` | 2 | 语义不同但可用查询无法区分 |
| `no_drift` | 2 | 隐藏 ID 不同，操作语义等价 |
| `mixed` | 8 | 单位×更新模式×默认范围的 2×2×2 组合 |

这些是候选支持集的世界数。当前生成器按实际世界语义去重，因此 `no_drift` 虽有两个隐藏 ID，但每个公开任务只生成一个实际 episode 世界；其他分组按上表生成。生成后的实际数目、去重和过滤数由 manifest 再验证。同一模式跨三个域的实例不能机械地算作更多独立工具语义；三个域共享数值赋值、集合更新两种底层算子。

当前任务生成器使用局部 `random.Random(f"{domain}:{seed}")`，数值系数从 2–300 取值，新增集合项从 1,000 个编号中抽取 2–3 个。域名进入随机流，避免相同 seed 跨域复用相同潜在数值和集合编号。实例唯一性由实际内容哈希检查；扩大取值空间本身不是泛化结果。

## 3. 公开与私有字段

| 类别 | 字段/内容 | 使用位置 |
|---|---|---|
| 公开上下文 | domain、instruction、legacy_docs、initial_state、tools、queries、candidates、query_budget | 策略输入；沙箱 context 的 task_id 在策略 DTO 中移除 |
| 公开执行历史 | 实际发出的 query/action、实际收到的 observation | 策略输入 |
| 公开运行状态 | remaining_budget、当前可用候选 | 策略输入 |
| 公开候选变化范围 | uncertainty_contract：各维度允许值/笛卡尔积或去 ID 支持集 | 所有策略与 oracle 共同获得；不指定真实世界 |
| 私有世界 | world_id、unit_factor、update_mode、default_scope、observable | 仅生成器、环境、oracle |
| 私有监督 | acceptable_decisions、oracle 值与诊断、隐藏可能世界集合 | 训练标签或评估；不进特征/prompt |
| 数据管理信息 | group_id、split、模板族、变更组合、generator revision、seed | 切分/审计；不得成为模型捷径 |

允许的查询返回可以包含已查询得到的单位或模式信息；uncertainty_contract 可包含所有候选值，但不指出哪一个是真的。禁止的是未查询的真实值通过旁路泄漏。字段名扫描只是辅助措施，主要检查是同公开任务、同候选支持集跨真实世界初始输入完全一致，以及提示/特征只由公开 DTO 生成。主实验假设部署时知道候选变化范围，不研究完全未知版本发现。

候选动作必须由公开任务和固定候选生成器决定。候选列表的长度、顺序、参数范围和描述不能泄露真实世界。该固定候选设定降低了问题难度，应明确写入模型结果，不能宣称完成开放参数生成。

## 4. 决策训练 JSONL

每行结构与训练接口一致：

```json
{
  "id": "opaque decision-row identifier",
  "group_id": "one public task and all its world branches",
  "split": "train",
  "observation": {
    "context": {},
    "history": [],
    "candidates": [],
    "remaining_budget": 3
  },
  "acceptable_decisions": [
    {"type": "query", "name": "inspect_units", "arguments": {}}
  ]
}
```

例子仅展示结构，不表示该查询对所有任务都最优。实际记录必须有非空候选和非空合法目标集合；每个目标必须能对应到候选。可附 `messages` 供人工审查，但 HF 训练提示从 `observation` 重新构建，不能信任附带的任意文本字段。

同一公开前缀若具有多个等价最优下一决策，保留默认 act-first 次级规则选中的集合：相同最坏查询成本下能行动则优先行动。它不是所有最优动作与查询的并集；完整集合用于独立消融。CPU 训练使用 `-log Σ_{a∈A_valid} p(a|o)`；语言模型路径使用合法决策序列概率质量和，最后 assistant 输出之外的 token 掩码。训练输入不包含教师解释隐藏世界的文字。

## 5. 标签生成与质量检查

ExactOracle 从有限可能世界及公开历史计算集合标签，模型不可访问真实世界选择。世界之间的后续策略须在相同观测历史下作相同决策；不能让 oracle 在每个隐藏世界分别选最有利动作后把它们合并冒充稳健策略。

标签区分：

- 当前已具备共同可完成动作：不需继续识别版本。
- 仍存在互不相容动作：按剩余预算选择只读证据。
- 所有可用查询仍不能消除关键歧义且没有统一完成策略：暂停。

验证要求：

1. 小例穷举与 DP 标签一致；所有合法目标可被执行器接受。
2. query 前后业务状态相同；scope 与集合不变量独立检查。
3. 无漂移组不因隐藏 ID 被监督为必须查询。
4. 不可辨识组不得依据真实 world 产生不同提示；若共同动作存在，则不能一律监督暂停。
5. 不可逆错误的后果必须保留，不能用重置后的数据库生成“成功”标签。
6. 重复样本、候选顺序、参数量级和不透明 ID 的捷径检查；必要时做字段消融与重新排列候选的敏感性测试。
7. 相同规范化公开 observation 必须有一致目标集合；若因私有 suite 支持集不同而产生矛盾，修正公开 uncertainty_contract 或统一 teacher 支持集，不能直接当标签噪声训练。

人工检查不能替代可执行真值测试；LLM judge 不能成为唯一标签来源。

## 6. 切分与污染控制

`group_id` 覆盖同公开任务的全部世界、前缀、预算变体和轨迹。先分组切分，再生成各策略/教师记录。任何同源版本跨训练/测试的情况都必须失败退出。`semantic_group` 去掉 task_id、seed、指令前缀和 query_budget 后按内容哈希，另用 `seen_groups` 去重，不以不同 ID 充当新任务。

实际切分为：

- calendar 全部进入 test；travel/catalog 按语义组哈希约 60%/20%/20% 切分。
- mixed 组合只为本来已在 test 的来源组生成。train/dev 来源组的 mixed 变体不会出现在测试集。
- test 使用不同文字前缀，基础指令结构未改变；`instance_and_prefix` 只表示实例与弱前缀扰动，不称强语言模板外推。
- calendar 与另外两域共用底层算子；这是域名、工具名、字段/单位迁移，不称未见操作机制泛化。

本轮已生成的 [CPU 数据 manifest](../experiments/cpu/dataset_manifest.json) 使用每域 60 个 seed、calendar 留出、查询预算 4，记录 180 个语义来源组、2,212 个世界实例和 3,006 条决策记录；世界实例 train/dev/test 为 729/225/1,258，决策记录为 1,053/325/1,628。这些是该 manifest 的实际规模，不等于独立训练任务数；后者需按来源组计数。修改生成器或来源组定义会改变分布，后续版本须引用对应 manifest。未来强模板或更多独立算子家族外推须另增生成器和 split，不能用协议计划冒充已完成。

无外部基准数据混入，不下载或公开 AppWorld 加密 bundle 的任务/数据库/解决方案。未来如使用 ToolSandbox、AgentGym 或其他第三方样本，必须另建来源、许可、版本和污染审查，不能继续使用“纯自产”说明。

## 7. 统计、用途与限制

每份导出应附：生成器与 schema 版本、配置哈希、生成时间、随机 seed、每域/分组/模板族数量、私有世界数、决策行数、去重数、过滤原因、split 来源组清单、数据 SHA-256。逐 episode 结果区分实际 `success`、`robust_success`、`uncertified_actions`、暂停、预算耗尽和系统异常；盲猜在真实世界碰巧成功不能自动视为稳健成功。

推荐用途是验证有限环境的信息需求、训练候选决策与研究集合监督。限制包括固定候选、少量域、手工语义、无观察噪声、无并发、无真实鉴权与用户歧义、写锁人为简化。它适合工程作品和机制证伪，尚不能代表生产 Agent 质量、真实 GUI 操作或大规模 API 迁移能力。

数据发布随项目许可与实际生成器版本进行；若未来引入任何第三方内容，应单独标注。模型训练记录、公开查询返回与隐藏答案分离发布：公开训练标签是允许的，但评测时策略只能访问相应公开观测，不能把随仓库附带的评测答案读入。
