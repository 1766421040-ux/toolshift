# ToolShift 工程范围与下一研究门槛

审查日期：2026-10-20。本文保留从首版局限到下一版门槛的设计过程。耦合诊断 CPU 扩展现已独立实现并执行，第 8 节记录完成范围；它没有修改 v1 数据或模型成绩，也没有执行结构留出的学习实验。

## 1. 首版完成了什么，复杂度停在哪里

ToolShift 已形成独立合成数据到训练、执行评估的工程通路。它的价值是让信息隔离、不可逆写入和查询决策可以检查、复算和证伪；当前结果不支持“学习策略优于规则”。

| 工程环节 | 首版实际范围 | 仍不能由此宣称的能力 |
|---|---|---|
| 数据库与执行 | 三个独立模拟域，真实 SQLite 更新、字段首次提交锁定、保护记录与已有集合项、执行日志 | 生产业务服务、跨应用鉴权、并发事务、真实用户需求处理 |
| 工具与任务 | 每域两个写工具；两个必要写步骤；数值单位、append/replace、默认范围变化 | 六种独立工具机制：六个名称实际共享两类算子 |
| 数据与信息边界 | 自产 fixtures；来源组隔离；所有策略共享公开候选变化范围；实际世界和 oracle 标签不进入策略观测 | 未知工具版本发现、自由参数生成、真实 API 迁移 |
| 教师与监督 | 有限世界 DP；行动后仍存在共同完成策略的检查；多个可接受候选的集合监督 | 任意现实环境的安全保证、一般最优 Agent 算法 |
| 学习 | CPU 候选评分器训练；独立的 HF/LoRA 训练与推理路径；实际 MPS 小规模 smoke run | 已完成多 B 模型 QLoRA、正式 LLM 效果提升 |
| 评估与回放 | 保存逐 episode 公开轨迹、私有评分、成本、暂停与错误；数据与运行清单可追溯 | 外部大型基准复现、无人工假设的生产可靠性 |

当前 [数据 manifest](../experiments/cpu/dataset_manifest.json) 是 180 个来源组、2,212 个世界实例、3,006 条决策记录。增加 seed 只扩大实例数。calendar 留出仍使用相同的两类算子；指令前缀变体仍是同一结构，不能据此主张未见操作家族或强语言模板泛化。

对照 [AppWorld 官方 README](https://github.com/StonyBrookNLP/appworld)，其作者声明 9 个应用、457 个 API、100+ 数据表和约 100 个模拟用户。其任务涉及多应用业务依赖，私有测试检查执行后的数据库状态。ToolShift 借鉴的是“按实际状态判分、把私有答案留在评估器”的工程原则，没有复现其覆盖面。不能把 ToolShift 的三域与 AppWorld 的三个完整应用等量比较，也不能用大量合成行数抵消业务结构的差距。外部源码与许可审查见 [reference_audit.md](reference_audit.md)。

## 2. 当前结果如何限制研究主张

已保存的 [static 结果](../experiments/cpu/static/summary.json) 与 [oracle 结果](../experiments/cpu/oracle/summary.json) 在同一批 1,258 个 test 世界实例上，实际成功率、稳健成功率与平均查询成本相同：

| 指标 | Static | 有限 Oracle |
|---|---:|---:|
| 全部实例稳健成功率 | 88.24% | 88.24% |
| 可稳健完成实例的成功率 | 100% | 100% |
| 全部实例平均查询成本 | 1.1765 | 1.1765 |
| 不可辨识实例数 | 148 | 148 |
| 不可辨识实例错误行动率 | 0% | 0% |

88.24% 的分母包含 148 个无法稳健完成的实例。两种方法在这些实例上暂停，不能写成“整个测试集 100% 成功”。不可辨识性还可从公开支持集中的可观测性字段知道，并非策略自行探索发现。

这个结果有明确结构原因：初态已知，允许变化范围已知，两个必要写步骤几乎独立。显式 `scope=current` 消除了范围问题；对确有歧义的单位和更新模式分别查询即可。低成本查询各自直接揭示一个必要字段。因此有限 oracle 的规划在当前分布上可以压缩成很短的静态规则。

“行动不必等到唯一版本被识别”可以作为首版机制演示；“集合监督让模型学到比强静态规则更好的查询策略”目前没有证据。学习模型与 LoRA 可以证明训练工程可执行，不能替代这项对照结论。后续若更换任务分布，必须重新做强静态比较，不能只沿用旧的固定查询规则制造优势。

当前 `robust_success` 还要求实际成功，且执行轨迹上每次写动作通过私有 oracle 的支持集可完成性审计。它只是在已声明有限支持集和动作界内的轨迹审计，不等于检查了策略所有未执行分支，更不等于现实环境的无条件安全证明。

## 3. 建议的单一扩展：有耦合关系和不同成本的诊断证据

下一版继续保留现有 SQLite 两步写入，不增加域数。只改变**证据获取结构**：候选语义之间有公开的耦合关系，一个便宜查询的结果会改变下一条应查证据；查询成本也不再相同。这样“需要哪个字段”取决于已经看到的结果，不能总写成固定查两个字段。

业务解释是分批发布的接口迁移：A 发布队列可能修改单位，B 发布队列可能修改集合更新语义。服务属于哪个队列未知；迁移公告只公开两个队列的允许变化及查询收费。这里没有增加隐藏业务状态或并发，以免把多个难点同时改变。

以下四世界最初是新协议的手算验收例，现已在独立 CPU 扩展中执行，详见第 8 节。所有世界仍允许显式限定目标范围，初始数据库与目标相同。

| 语义世界 | 发布队列 | 单位因子 | 集合模式 |
|---|---|---:|---|
| w1 | A | 1 | append |
| w2 | A | 60 | append |
| w3 | B | 1 | append |
| w4 | B | 1 | replace |

世界名称只用于解释，不进入策略输入。四行去 ID 后的联合支持集公开，真实所在行隐藏。w1 与 w3 的正确写动作相同，不必为了完成业务区分它们。

建议的公开查询契约：

| 查询 | 返回内容 | 成本 |
|---|---|---:|
| `inspect_route` | A 或 B | 1 |
| `inspect_units` | 实际单位因子 | 2 |
| `inspect_update_mode` | 实际集合模式 | 2 |
| `read_contract` | 当前单位与集合模式 | 4 |

查询的返回映射和费用公开，实际返回只在支付后可见。现有 `read_state` 只返回公开业务状态，不泄露发布队列；旧的成本为 3 的完整契约接口不能悄悄保留为额外捷径。

在这个真值表上，先查队列、A 分支查单位、B 分支查更新模式，最坏查询成本为 3。先固定查单位与更新模式，最坏成本为 4；完整刷新为 4。不存在成本小于 3 的稳健完成策略：唯一成本为 1 的查询不能单独确定两步所需语义，任何成本为 2 的单次查询也至少留下一个不能共同完成的返回分支。这个结论是对表格的推导，不是实验结果或算法创新。

这一例子证明了结果依赖的查询顺序有意义，**不证明学习或多步规划超过强规则/贪心**。知晓联合支持集的分支静态规则同样能做到 3；按信息收益/成本的贪心在此例也可能做到 3。应完整保留这些对照。

## 4. 下一版必须给足能力的对照

所有方法接收相同联合支持、查询返回映射、查询费用、业务工具语义与公开历史，不读取实际世界。静态方法允许依据返回值分支，不能把“static”偷偷限定成固定查两字段。

| 对照 | 必须允许的能力 | 它能推翻什么 |
|---|---|---|
| 最强人工分支规则 | 根据联合支持推断已确定字段；按队列分支；可主动行动或暂停 | 若已达 oracle，推翻该任务需要学习 |
| 完整刷新 | 支付真实费用读取所有行动相关语义 | 检验有选择地查询是否有任何价值 |
| 成本感知版本贪心 | 按查询成本减少最坏剩余语义候选数；并列按预先固定规则 | 检验多步规划是否超出简单信息分割 |
| 成本感知动作贪心 | 先合并业务上等价的候选；按成本减少冲突动作/后续完成方案 | 避免拿只关心版本 ID 的弱贪心替代任务相关基线 |
| 深度 2/3 的有限前瞻规则 | 根据相同公开有限模型搜索，并报告运行成本 | 检验学习收益是否只是替代很小的规划器 |
| 编译的精确决策树 | 对相同公开模型离线求解，再按真实查询返回走树 | 若精确树很小且便宜，推翻用学习摊销规划的必要性 |
| ExactOracle | 统一未来策略和不可逆写入的完整有限 DP | 检查教师与评分，给有限模型内的界 |

“版本贪心”计数应在去 ID 语义世界上进行；不能通过复制同义 world ID 改变收益。动作贪心的等价关系、分母、无收益时如何选择与 tie-break 须先定义，再生成测试集。若方法利用查询返回的完整有限表，这种结构知识也必须提供给可部署规划/静态对照；它与额外读取真实返回不同。

只有最强同信息基线做不到、学习方法又稳定做到的部分才可成为学习增量。单独超过“固定两字段”不够。若编译决策树在可接受资源内达到最优，学习模型的部署价值可能为空；这应成为结果，而不是排除决策树的理由。

## 5. 最小实施与可证伪门槛

先做 CPU 结构验收，再决定是否投入模型训练。以下保留分阶段门槛：四世界和费用变化已执行，随机分区扩展已执行但未完成图同构去重，结构留出及模型训练仍未执行，详见第 8 节。

1. **四世界验收。** 穷举全部世界与预算，验证成本 3 的分支策略与 DP 一致，预算不足时不能靠幸运写入取得稳健成功。成本为 3 的完整策略不是从私有实际世界选择的四条独立答案。
2. **改变成本。** 至少同时测试 `(队列, 单位, 模式)=(1,2,2)、(1,1,1)、(3,2,2)`。完整刷新价格也独立报告和变化。前两种分别出现优势或持平，第三种固定查两个字段的最坏成本 4 优于队列优先的 5；策略必须真的读取费用。不能只挑队列查询有利的配置。
3. **改变耦合。** 再生成小规模、预先声明的 8–16 个非同构支持/查询覆盖图，逐图枚举 4–16 个世界；这些数字是试验设计范围。包含独立变化、耦合变化、行为等价世界和无用查询。若都是四世界图换名字，不能称新问题族。
4. **按结构留出。** 同一支持图、费用变体、域名置换及其全部轨迹归为同源结构族；训练/开发/测试按图族切分。另列新费用插值与外推，不把同一诊断树换单位或名称当成结构外推。
5. **基线先行。** 运行完整刷新、人工分支、两种贪心、有限前瞻、编译精确树与 DP。若规则已全部最优，继续训练只能标注为策略模仿/工程实验，不宣称获得新的研究优势。
6. **有缺口才训练。** 若至少一种未见结构上存在可复现的规划/成本缺口，再在同数据、模型、训练预算下比较集合监督、单路径监督、版本识别监督、贪心监督。不能通过增加标签或放宽预算给主方法单独优势。

主要判据仍是稳健完成约束下的查询费用，逐结构族报告最坏费用与平均费用，明确二者不是同一个目标。minimax 教师只保证前者；不能因为平均费用更低就称违背或超过 minimax 下界。低费用但更多暂停或猜测不算改进。

学习继续门槛沿用预注册思想：相对最强同信息且满足部署资源约束的可执行基线，配对稳健成功率差的置信下界不低于 −2 个百分点，平均查询费用至少下降 20%，并给出按结构族聚类的置信区间。阈值是继续投入的工程选择，不能代替显著性或原创性论证。精确树若同样便宜且最优，学习方法无法通过这道成本门槛，应停止性能优势主张。

可另外研究“编译/推理开销”的摊销价值，但必须预先声明部署时间或内存约束，计入 oracle 标签生成、精确树编译与模型训练的全部成本，报告部署调用次数对应的盈亏点。不得事后人为卡住静态方法的资源以制造优势。当前四世界例子没有这种摊销需求。

## 6. 哪些接口必须另立版本

| 变更 | 必须修改和检查的地方 |
|---|---|
| 联合候选包含发布队列 | 扩展 WorldSpec 与去 ID 联合语义；相同支持集跨实际世界初始输入完全相同 |
| 查询具有可配置费用和覆盖 | 新 QuerySpec 公开映射与费用；预算过滤、执行器计费、教师递归使用同一来源；不能仍依赖全局固定 `QUERY_COSTS` |
| 返回决定下一条证据 | 查询模型按当前公开历史筛支持集；相同公开历史始终对应同一集合标签 |
| 完整刷新含义变化 | 明确返回字段、费用和是否包含队列；不能让某方法免费取得更多语义 |
| DP 与缓存 | 状态/缓存键包含查询目录、费用、支持关系和已提交状态；跨不同查询图不能误用旧缓存 |
| 数据切分 | 新 schema/generator revision、结构族 ID、来源组哈希和独立 manifest；不得复用旧盲测分数 |
| 评估与报告 | 保留执行路径稳健性审计与错误统计；新增结构族、费用配置、最坏路径费用和规划资源 |

初态、目标、写锁和状态不变量保持现有定义，有助于把变化归因到证据结构。真实业务状态部分未知是另一条后续路线；若加入，应把支持集扩展为“版本×业务状态”，并重新证明观测充分性，不能混入本版后仍称只改变查询结构。

## 7. 求职作品可以怎样准确表述

当前可用于项目经历的表述：

> 实现 ToolShift 有状态工具调用实验系统，构建三域 SQLite 沙箱与单位、集合更新、默认作用范围变更任务；设计公开观测与私有真值隔离、有限世界规划教师和多合法决策集合监督，完成候选策略训练、分组留出评估与轨迹回放。对比强静态规则与精确规划，定位当前任务被规则解决的边界，并独立实现耦合证据查询 CPU 实验。

真实训练可单列为：

> 打通 Hugging Face/PEFT LoRA 训练与候选推理流程，在 Apple MPS 上使用 SmolLM2-135M 完成 4 步 smoke run 和 200 个优化步的正式训练，采用 assistant token 掩码与多合法答案集合目标，并保存模型、配置及训练记录。

第二段依据 [实际 smoke summary](../experiments/mps_smoke/summary.json) 和 [正式训练 summary](../experiments/lora_main/training_summary.json)。训练完成不等于能力提升，不能改写成“显著提升 Agent 成功率”。CUDA QLoRA 配置与本机 MPS LoRA 分别描述；CPU 候选评分器不称 LLM。

正式 LoRA 的 51-episode 独立评估已完成：底模全部暂停；LoRA 实际成功 23 个、
稳健成功 8 个，15 个任务破坏保护约束，所有任务查询数为 0。不能主张它已经学会
证据获取。详见 [结果报告](results.md)。GitHub 发布以可访问仓库地址与对应提交
为准；“工程可复现”“研究效果成立”“原创性已确立”是三个不同的完成标准。

可以称“完成可运行研究工程/原型与基线实验”。暂不称“大规模 Agent 平台”“复现 AppWorld”“自主发现未知 API 变化”“证明原创算法优于现有方法”或“生产级安全保证”。工程质量应由安装与执行说明、测试、固定配置、真实结果、失败样例和许可来源来证明。

## 8. 已完成的独立诊断扩展

[耦合诊断协议与结果](diagnostic_graph.md) 已执行 3 个固定费用配置和 64 个未筛选随机配置，共 374 个语义世界、5 种算法、1,870 次真实 SQLite 执行。公开模型给所有算法相同的候选语义、查询分区与费用；实际世界仅由评估器持有。精确行动充分性树、精确版本识别树、两种贪心和完整刷新均保留，最大精确树为 15 个节点。

行动充分性规划在 17/67 个配置上比完整版本识别减少最坏查询费用，在 15/67 个配置上优于动作相关贪心，其余持平；各方法在所声明有限世界与充足预算下全部通过实际状态验证。这支持查询机制差异，仍不能说明学习必要。费用以有理数累计，15 项测试与 2,792 次双写序 SQL 检查通过。

这个独立实现没有增加新 WorldSpec 字段：四世界中的发布队列用已有默认范围的两个候选组表示，作用范围仍可被显式 `current` 消除；额外诊断端点的公开分区可与这一组别耦合。它绕开 v1 固定查询目录，不修改运行中的 Sandbox 语义或原训练数据。当前统计为 65 个不同的带标签支持/分区结构，尚未做图同构去重，不能称为 65 个独立图族。

因此第 5 节的完整结构族切分、强语言模板、结构留出学习和与模型训练预算匹配的消融仍未完成。该扩展的 CPU 机制成绩与 v1 LoRA 成绩分别报告，不能把精确决策树的查询收益写成 LoRA 改进。
